# PRD - Tika (티켓 기반 칸반 보드 Todo 앱)

## 1. 제품 개요

Tika는 개인 사용자가 할 일을 티켓 단위로 관리하는 **칸반 보드 기반 Todo 앱**이다.
사용자는 티켓을 생성하고, 드래그 앤 드롭으로 진행 상태를 이동시키며, 계획일과 실제일을 함께 기록해 작업의 계획 대비 실적을 추적할 수 있다.

Next.js App Router 기반으로 프론트엔드(`src/client/`)와 백엔드(`app/api/`, `src/server/`)를 디렉토리 수준에서 분리하고, `src/shared/`에서 타입과 Zod 검증 스키마를 공유하는 구조를 따른다.

## 2. MVP 범위

| 항목 | 내용 |
|---|---|
| 사용자 | 단일 사용자 (인증 없음) |
| 보드 컬럼 | 고정 4컬럼: Backlog / TODO / In Progress / Done (커스텀 컬럼 불가) |
| 티켓 기능 | 생성(Create) / 조회(Read) / 수정(Update) / 삭제(Delete) |
| 상태 이동 | 드래그 앤 드롭(@dnd-kit)으로 컬럼 간 이동 |
| 일정 필드 | 계획시작일, 시작일, 계획종료일, 종료일 |

## 3. 2차 범위 (MVP 제외)

아래 항목은 2차 스펙으로, 이번 MVP에서는 구현하지 않는다.

- 사용자 인증 (로그인/회원가입/세션)
- 커스텀 컬럼 (컬럼 추가/삭제/순서 변경)
- 멀티 사용자 (공유 보드, 권한, 협업)
- 라벨 / 코멘트
- 파일 업로드 (첨부파일, 이미지)

## 4. 사용자 시나리오

1. **할 일 등록**: 사용자가 Backlog에 새 티켓을 생성하고 제목, 설명, 계획시작일, 계획종료일을 입력한다.
2. **상태 이동**: 작업을 시작하면 티켓을 TODO → In Progress로 드래그 앤 드롭하며, 이때 시작일이 기록된다.
3. **수정/삭제**: 진행 중 내용이 바뀌면 티켓 상세를 열어 필드를 수정하거나, 더 이상 불필요한 티켓을 삭제한다.
4. **완료 확인**: 작업이 끝나면 티켓을 Done으로 이동시키고 종료일을 확인하여 계획 대비 실제 진행 상황을 검토한다.

## 5. 핵심 기능 목록 (FR-001 ~ FR-008)

> 상세 인수 조건 및 테스트 케이스는 각각 `REQUIREMENTS.md`, `TEST_CASES.md`에서 정의한다.

| ID | 기능 | 설명 |
|---|---|---|
| FR-001 | 티켓 생성 | 사용자는 제목(필수), 설명, 계획시작일, 계획종료일을 입력해 Backlog에 새 티켓을 생성할 수 있다. |
| FR-002 | 티켓 목록/상세 조회 | 사용자는 보드에서 컬럼별 티켓 목록을 확인하고, 티켓을 클릭해 상세 정보(설명, 일정 4종, 현재 상태)를 조회할 수 있다. |
| FR-003 | 티켓 수정 | 사용자는 티켓의 제목, 설명, 계획시작일, 계획종료일, 상태를 수정할 수 있다. |
| FR-004 | 티켓 삭제 | 사용자는 티켓을 삭제할 수 있으며, 삭제 시 확인 절차를 거친다. |
| FR-005 | 드래그 앤 드롭 상태 이동 | 사용자는 티켓 카드를 드래그하여 다른 컬럼으로 이동시킬 수 있으며, 이동 즉시 상태가 반영된다. |
| FR-006 | 고정 4컬럼 보드 렌더링 | 보드는 Backlog / TODO / In Progress / Done 4개 컬럼을 고정 레이아웃으로 렌더링하며 컬럼 추가/삭제는 지원하지 않는다. |
| FR-007 | 일정 자동/수동 기록 | 티켓은 계획시작일·계획종료일(수동 입력)과 시작일·종료일(상태 이동 시 자동 기록, 수동 수정 가능)을 함께 관리한다. |
| FR-008 | 완료 확인 | 티켓이 Done 컬럼으로 이동하면 종료일이 기록되고, 계획일 대비 실제일 차이를 보드/상세에서 확인할 수 있다. |

## 6. 기술 스택

| 영역 | 기술 | 선정 이유 |
|---|---|---|
| Framework | Next.js 15 (App Router) | Route Handler로 API와 프론트를 한 저장소에서 관리하면서도 `app/api/` ↔ `src/client/` 디렉토리 분리 구조를 자연스럽게 지원 |
| Language | TypeScript (strict) | `any` 금지, 공유 타입(`src/shared/types`) 기반 프론트-백엔드 계약을 컴파일 타임에 보장 |
| Frontend | React 19 | 함수 컴포넌트 + 훅 기반 개발, Next.js App Router와의 호환성 |
| Styling | Tailwind CSS 4 | 유틸리티 클래스로 칸반 보드의 컬럼/카드 레이아웃을 빠르게 구현, 디자인 시스템 없이도 일관된 스타일 유지 |
| Drag & Drop | @dnd-kit/core, @dnd-kit/sortable | 접근성(a11y)을 고려한 드래그 앤 드롭 구현체로, 컬럼 간 카드 이동에 필요한 sortable 컨텍스트를 제공 |
| ORM | Drizzle ORM | 타입 안전한 쿼리 빌더로 raw SQL 없이 스키마-쿼리 일관성 확보, 경량 런타임 |
| DB | Vercel Postgres (Neon) | Vercel 배포 환경과의 통합, 서버리스 환경에 적합한 커넥션 풀링 |
| Validation | Zod | `src/shared/validations`에서 스키마를 정의해 프론트(폼 검증)와 백엔드(요청 검증)에서 동일 스키마 재사용 |
| Testing | Jest + React Testing Library | 컴포넌트/서비스 단위 테스트, TDD 사이클(Red-Green-Refactor) 지원 |
| Deployment | Vercel | Next.js와의 네이티브 통합, Postgres(Neon)와 동일 플랫폼 배포로 설정 최소화 |

## 7. 와이어프레임 참고

보드 레이아웃은 **좌측 Backlog 사이드바 + 우측 3컬럼 보드(swimlane)** 구조를 따른다.

```
┌───────────────┬──────────────────────────────────────────────────┐
│               │                  Tika Board                       │
│   Backlog     ├──────────────────┬──────────────────┬────────────┤
│  (사이드바)    │      TODO         │   In Progress     │    Done    │
│               │                   │                   │            │
│ [+ 새 티켓]    │  ┌─────────────┐  │  ┌─────────────┐  │ ┌────────┐ │
│               │  │ 티켓 카드    │  │  │ 티켓 카드    │  │ │티켓카드│ │
│ ┌───────────┐ │  └─────────────┘  │  └─────────────┘  │ └────────┘ │
│ │ 티켓 카드  │ │                   │                   │            │
│ └───────────┘ │  ┌─────────────┐  │                   │ ┌────────┐ │
│ ┌───────────┐ │  │ 티켓 카드    │  │                   │ │티켓카드│ │
│ │ 티켓 카드  │ │  └─────────────┘  │                   │ └────────┘ │
│ └───────────┘ │                   │                   │            │
└───────────────┴──────────────────┴──────────────────┴────────────┘
```

- 좌측 **Backlog 사이드바**: 아직 착수하지 않은 티켓 목록과 신규 티켓 생성 진입점을 배치한다.
- 우측 **3컬럼 swimlane**: TODO / In Progress / Done 컬럼을 가로로 배치해 진행 상태를 한눈에 비교할 수 있게 한다.
- 티켓 카드는 제목, 계획종료일(또는 종료일)을 요약 정보로 노출하고, 드래그 핸들을 통해 컬럼 간 이동이 가능하다.
- 상세 명세는 `COMPONENT_SPEC.md`에서 Props와 동작을 정의한다.
